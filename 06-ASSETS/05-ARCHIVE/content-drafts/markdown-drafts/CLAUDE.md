## FILE NAMING RULES
- Use ALL-CAPS for markdown files: `VIDEO-SCRIPT.md`, `YOUTUBE-SHORT-SCRIPT.md`
- Use lowercase-with-dashes for media: `lesson1-VERTICAL.mp4`, `clip-01-woman-tablet.mp4`
- Never add dates to filenames — dates cause confusion about which is "latest"
- Never suffix files with `-v2`, `-new`, `-updated`, `-final` — that means you have a duplicate problem, not a versioning solution

## DUPLICATE & CLUTTER RULES — ENFORCE EVERY SESSION

### When creating a new version of a file:
1. READ the existing file first
2. If the new version supersedes it completely → DELETE the old one, save the new one in place
3. If both versions have unique value → MERGE them into one file, delete the old
4. Never leave two files that serve the same purpose in the same folder

### When you create a new script or process doc:
- Check if a similar one already exists in 05-SCRIPTS/ first
- If yes, update that file — do not create a new one

### Empty folders:
- Delete immediately — never leave empty folders

### Completed project folders (article is live, video is done):
- All working files (prompts, clip instructions) should be consolidated inside the article's own subfolder
- 05-SCRIPTS/ is for ACTIVE processes only — not finished project artifacts

### Specific cleanup rules:
| If you find... | Do this |
|---|---|
| Two files with similar names in same folder | Read both, merge or delete older, keep one |
| A process .md file AND a shorter .md of the same process | Delete the shorter/older one |
| An empty folder | Delete it |
| A script file at 02-LINKEDIN/articles/ root level | Move it into its proper article subfolder |
| A file named with `-v2`, `-copy`, `-new`, `-final` | The original is the duplicate — resolve it |
